# Развёртывание на Synology NAS (Container Manager)

Удалённый режим: сервер работает на NAS в Docker, наружу выходит через обратный прокси DSM по HTTPS. Каждый сотрудник входит через свой портал Битрикс24, и инструменты работают от его имени.

Адреса в примерах: сервер `https://mcp.example.synology.me`, MCP-адрес для клиентов `https://mcp.example.synology.me/mcp`. Замените на свои.

## 1. Локальное приложение на портале Битрикс24

1. Откройте портал, раздел «Разработчикам» (или «Приложения» → «Разработчикам») → «Другое» → «Локальное приложение».
2. Тип приложения: «Серверное». Отметьте «Приложение использует только API».
3. Путь обработчика: `https://mcp.example.synology.me/b24/callback`. Если приложение уже создано раньше (например, с временным адресом `http://localhost:8765/b24/callback`), замените путь обработчика на этот.
4. Права: `user`, `department`, `task`, `im`, `disk`, `calendar`, `crm`, `sonet_group`.
5. Сохраните. Скопируйте `client_id` (вида `local.…`) и `client_secret`: они понадобятся в `.env`.

## 2. Сертификат и обратный прокси в DSM 7.2

Порт 443 NAS должен быть доступен из интернета, а `mcp.example.synology.me` указывать на NAS.

1. Панель управления → Безопасность → Сертификат → Добавить → Получить сертификат от Let's Encrypt. Домен `example.synology.me`, альтернативное имя `*.example.synology.me` (поддомены).
2. Панель управления → Портал входа → Дополнительно → Обратный прокси → Создать:
   - Источник: протокол HTTPS, имя хоста `mcp.example.synology.me`, порт 443.
   - Назначение: протокол HTTP, имя хоста `localhost`, порт 3000.
3. Правка правила → «Дополнительные настройки»: увеличьте время ожидания чтения прокси (например, до 300 секунд). Инструменты вроде `call_summaries` могут идти дольше стандартных 60 секунд.
4. Панель управления → Безопасность → Сертификат → Настройка: назначьте сертификат Let's Encrypt службе `mcp.example.synology.me`.

Порт контейнера публикуется только на `127.0.0.1:3000`, поэтому к серверу можно обратиться лишь через этот прокси (сервер доверяет заголовкам `X-Forwarded-*` одного прокси).

## 3. Настройка и запуск

1. Скопируйте репозиторий на NAS (например, в `/volume1/docker/bitrix24-mcp`).
2. Создайте `.env` из примера и заполните:
   ```bash
   cp .env.example .env
   openssl rand -base64 32   # значение для SECRET_KEY
   ```
   Обязательные: `PUBLIC_URL=https://mcp.example.synology.me`, `B24_PORTAL`, `B24_CLIENT_ID`, `B24_CLIENT_SECRET`, `SECRET_KEY`. Файл `.env` никогда не коммитится. Потеря `SECRET_KEY` делает сохранённые токены нечитаемыми, и всем придётся войти заново.
3. Container Manager → Проект → Создать: путь к папке репозитория, источник `docker-compose.yml`, запустить. Либо по SSH: `docker compose up -d --build`.
4. Данные (SQLite с зашифрованными токенами) лежат в именованном томе Docker `bitrix24-mcp-data` (в проекте Compose он может называться с префиксом, например `bitrix24-mcp_bitrix24-mcp-data`). Том создаётся с правами пользователя контейнера и переживает пересборку и обновление контейнера. Посмотреть: Container Manager → Том, или по SSH `docker volume ls`. Резервная копия: `docker run --rm -v bitrix24-mcp_bitrix24-mcp-data:/data -v "$PWD":/backup alpine tar czf /backup/mcp-data.tgz -C /data .` (точное имя тома смотрите в `docker volume ls`). Сброс (все сотрудники войдут заново): остановить проект и выполнить `docker volume rm <имя тома>`; `docker compose down -v` тоже удаляет том.
5. Проверка: `curl https://mcp.example.synology.me/healthz` возвращает `{"status":"ok"}`.

Логи: Container Manager → Контейнер → Журнал. Одна строка на запрос: `METHOD /path STATUS user=ID`.

## 4. Подключение клиентов

- claude.ai: Settings → Connectors → Add custom connector → URL `https://mcp.example.synology.me/mcp`. Дальше откроется страница входа портала Битрикс24 и страница согласия.
- Claude Code:
  ```bash
  claude mcp add --transport http bitrix24 https://mcp.example.synology.me/mcp
  ```
  Затем `/mcp` в Claude Code и вход через браузер.

## 5. Режим только чтения

В `.env`:

- `READ_ONLY=true` — для всех;
- `READ_ONLY_USERS=12,34` — ID пользователей, которым запись запрещена;
- `READ_ONLY_DEPARTMENTS=5,8` — ID подразделений (включая вложенные); требует права `department`.

Пользователь на странице согласия может сам выбрать режим только чтения. Изменения применяются после перезапуска контейнера; для уже выданных доступов списки перепроверяются при очередном обновлении токена.

## 6. Обновление

```bash
git pull
docker compose up -d --build
```

Данные в томе `bitrix24-mcp-data` сохраняются (не используйте `down -v`). В Container Manager то же самое: проект → Действие → Собрать заново.

## Прочие переменные

`KNOWN_CLIENT_HOSTS` (по умолчанию `claude.ai,claude.com,localhost,127.0.0.1`: остальные хосты требуют отдельной галочки на странице согласия), `B24_MEMBER_ID` (закрепить сервер за одним порталом), `B24_OAUTH_TOKEN_URL`. `PORT` (3000) и `DATA_DIR` (`/data`) заданы в образе, в `.env` их менять не нужно: порт контейнера должен оставаться 3000, иначе разойдутся проброс порта и обратный прокси.
