# Развёртывание на Synology NAS (Container Manager)

Вариант общей инструкции [deploy-docker.md](deploy-docker.md) для Synology DSM 7.2: HTTPS даёт встроенный обратный прокси DSM, контейнер запускается проектом в Container Manager. Здесь описано только то, что отличается; остальные шаги выполняются по общей инструкции.

Адреса в примерах: сервер `https://mcp.example.synology.me`, MCP-адрес для клиентов `https://mcp.example.synology.me/mcp`. Замените на свои.

## 1. Локальное приложение на портале Битрикс24

По общей инструкции: [раздел 1](deploy-docker.md#1-локальное-приложение-на-портале-битрикс24). Путь обработчика: `https://mcp.example.synology.me/b24/callback`.

## 2. Сертификат и обратный прокси в DSM 7.2

Порт 443 NAS должен быть доступен из интернета, а `mcp.example.synology.me` указывать на NAS.

1. Панель управления → Безопасность → Сертификат → Добавить → Получить сертификат от Let's Encrypt. Домен `example.synology.me`, альтернативное имя `*.example.synology.me` (поддомены).
2. Панель управления → Портал входа → Дополнительно → Обратный прокси → Создать:
   - Источник: протокол HTTPS, имя хоста `mcp.example.synology.me`, порт 443.
   - Назначение: протокол HTTP, имя хоста `127.0.0.1`, порт 3000 (или значение `HOST_PORT` из `.env`, если порт 3000 на NAS занят). Именно `127.0.0.1`, а не `localhost`: nginx в DSM может пойти на IPv6-адрес `::1`, а Docker публикует порт только на IPv4.
3. Правка правила → «Дополнительные настройки»: увеличьте время ожидания чтения прокси до 300 секунд. Инструменты вроде `call_summaries` могут идти дольше стандартных 60 секунд.
4. Панель управления → Безопасность → Сертификат → Настройка: назначьте сертификат Let's Encrypt службе `mcp.example.synology.me`.

Обратный прокси DSM сам передаёт заголовки `Host` и `X-Forwarded-*`, отдельно настраивать их не нужно.

## 3. Проект в Container Manager

1. Создайте папку проекта, например `/volume1/docker/bitrix24-mcp` (File Station → общая папка `docker`). Положите в неё [`docker-compose.yml`](../docker-compose.yml) из репозитория.
2. Рядом создайте `.env` и заполните по общей инструкции: [раздел 2](deploy-docker.md#2-настройка-и-запуск). На NAS порт 3000 часто занят: тогда добавьте строку `HOST_PORT=3030` и укажите этот же порт в назначении обратного прокси.
3. Container Manager → Проект → Создать: имя `bitrix24-mcp`, путь к папке проекта, источник «Использовать существующий docker-compose.yml», настройки Web Station не включать. Container Manager скачает образ и запустит контейнер.
4. Проверка: `curl https://mcp.example.synology.me/healthz` возвращает `{"status":"ok","version":"…"}` с номером запущенной версии.

Журнал: Container Manager → Контейнер → Журнал. Том с данными: Container Manager → Том.

Раздел «Реестр» в Container Manager ищет только на Docker Hub, поэтому образ из `ghcr.io` там не найти. Это не мешает: Compose скачивает его напрямую.

### Команды по SSH

Все команды `docker` из общей инструкции на NAS выполняются через `sudo`: обычный пользователь не имеет доступа к сокету Docker. Например, из папки проекта: `sudo docker compose up -d`. Container Manager в DSM 7.2 ставит Compose v2, команда `docker compose`; если её нет (старый пакет Docker), используйте `sudo docker-compose` с теми же аргументами.

## 4. Подключение клиентов и режим только чтения

По общей инструкции: [подключение клиентов](deploy-docker.md#4-подключение-клиентов), [режим только чтения](deploy-docker.md#5-режим-только-чтения).

Изменения `.env` вступают в силу только после пересоздания контейнера. В Container Manager: Проект → выберите проект → «Действие» → «Остановить», затем «Действие» → «Собрать». Кнопка «Перезапустить» для этого не подходит: она оставляет старые значения.

## 5. Обновление

В Container Manager: Проект → `bitrix24-mcp` → «Действие» → «Остановить», затем «Собрать». Благодаря `pull_policy: always` в `docker-compose.yml` при этом скачивается свежий образ из GHCR и контейнер пересоздаётся.

Если в вашем `docker-compose.yml` этой строки нет (проект создан до версии 1.2.2), добавьте её: «Действие» → «Изменить», строка `pull_policy: always` под `image:`. Без неё «Собрать» берёт уже скачанный образ, и обновление не приходит. Если в `docker-compose.yml` закреплена версия, сначала поменяйте её там.

По SSH: как в [общей инструкции](deploy-docker.md#6-обновление), через `sudo`.

Проверка после обновления: `curl https://mcp.example.synology.me/healthz` показывает новую версию.
