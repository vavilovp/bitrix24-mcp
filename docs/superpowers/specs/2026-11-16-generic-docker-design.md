# Универсальное развёртывание в Docker

## Зачем

Сервер и образ `ghcr.io/vavilovp/bitrix24-mcp` работают на любом хосте с Docker, но документация и комментарии описывают только Synology NAS. Нужно, чтобы проект читался как обычный Docker-проект, а Synology осталась одним из описанных способов развёртывания.

## Цели

- Основная инструкция описывает развёртывание на любом хосте с Docker и Compose.
- Инструкция для Synology сохраняется и остаётся рабочей.
- В комментариях к файлам нет привязки к NAS и DSM.

## Чего не делаем

- Поведение сервера, образ и `docker-compose.yml` (кроме комментариев) не меняются. Работающий NAS не затрагивается.
- Обратный прокси в комплект не входит: HTTPS каждый настраивает сам по примерам.
- Новый релиз не выпускается: в инструментах и образе изменений нет.

## Рассмотренные подходы

1. Caddy в комплекте (второй compose-файл, автоматический сертификат). Проще запуск на чистом сервере, но ещё один файл и ещё один сценарий на поддержку.
2. Только инструкция с примерами настроек прокси. **Выбран пользователем.**

## Что меняется

- `docs/deploy-docker.md` (новый, основной):
  - локальное приложение на портале Битрикс24;
  - `.env` и запуск через `docker compose up -d`;
  - требования к обратному прокси: HTTPS на публичном адресе, передача на `127.0.0.1:<HOST_PORT>`, ровно один прокси перед сервером, заголовки `Host`, `X-Forwarded-For`, `X-Forwarded-Proto`, таймаут чтения 300 секунд;
  - примеры: nginx (с certbot) и Caddy целиком, Traefik коротким фрагментом с метками;
  - подключение клиентов, режим только чтения, обновление, резервная копия, прочие переменные.
- `docs/deploy-synology.md`: остаётся только то, что относится к DSM (сертификат, обратный прокси DSM, проект в Container Manager, обновление через «Собрать», `sudo` по SSH). Общие разделы заменяются ссылками на `deploy-docker.md`.
- `README.md`: ссылка на общую инструкцию и отдельно на вариант для Synology; короткий раздел «Подключение в Claude» (свой коннектор в claude.ai и приложениях, команда для Claude Code, проверка).
- Комментарии в `docker-compose.yml`, `.env.example`, `server/http.js`: «обратный прокси» и «хост» вместо DSM и NAS.

## Решения исполнителя

- Примеры nginx и Caddy проверяются запуском проверки синтаксиса в контейнерах. Пример Traefik не проверяется вживую, это будет указано в PR.
- Номер версии не меняется.

## Проверка

- `npm test` и `npm run check` проходят.
- `docker compose config` принимает файл.
- Ссылки между документами ведут на существующие разделы.
